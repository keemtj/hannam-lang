한남랭의 에러는 두 종류입니다. `.hn`을 JS로 바꾸는 단계에서 나는 **컴파일 에러**와, 바뀐 JS가 실행되다가 나는 **실행 중 에러**입니다.

## 컴파일 에러

규칙에 맞지 않는 밈을 쓰면 변환하기 전에 에러가 납니다. 메시지에는 무엇이 잘못됐는지, 파일 이름과 위치(`파일:줄:칸`), 해당 줄의 코드 조각이 들어 있습니다.

```hn title="app.hn"
엄. 개수 = 1
예???? 개수 > 0 {
  무슨 발언이세요? 개수
}
```

```txt
'예'의 물음표는 1~3개만 쓸 수 있습니다 (4개) (app.hn:2:1)
2 | 예???? 개수 > 0 {
    ^
```

- `app.hn:2:1`은 2번째 줄 1번째 칸이라는 뜻입니다. 줄과 칸 모두 1부터 셉니다.
- `^`가 문제가 시작되는 위치를 가리킵니다.
- `hannam`은 이 메시지를 출력하고 종료 코드 1로 끝납니다. Vite에서는 dev 서버 화면에 에러 오버레이로 뜹니다.

### 자주 보는 메시지

| 메시지 | 원인과 해결 |
| --- | --- |
| `'예'의 물음표는 1~3개만 쓸 수 있습니다` | `예????`처럼 물음표가 4개 이상입니다. if는 `예?`, else if는 `예??`, switch는 `예???`입니다 |
| `'아뇨'는 1번(continue) 또는 4번(else)만 씁니다` | `아뇨아뇨`처럼 개수가 맞지 않습니다 |
| `'예??'(else if)는 '예?' 블록의 '}' 바로 뒤에서만 쓸 수 있습니다` | `예??`를 따로 썼습니다. 앞 블록의 `}`와 같은 줄에 `} 예?? 조건 {`로 씁니다 |
| `'무슨 발언이세요?' 뒤에는 띄어 쓰고 값을 적습니다` | `무슨 발언이세요?("a")`처럼 괄호를 붙였습니다. `무슨 발언이세요? "a"`로 씁니다 |
| `쉼표로 여러 값을 넘길 때는 괄호로 감싸지 않습니다` | `무슨 발언이세요? (a, b)`는 마지막 값만 출력됩니다. 괄호를 뺍니다 |
| `if 조건으로 쓰려면 '예? 예? 무슨 발언이세요?(...) {'처럼 '예?'를 한 번 더 씁니다` | 확인 창을 조건으로 쓸 때는 `예?`를 두 번 씁니다 |
| `import 경로에 확장자를 씁니다` | `"./store"` 대신 `"./store.hn"`처럼 확장자를 붙입니다 |
| `둥근 따옴표 '“' 대신 일반 따옴표를 쓰세요` | 휴대폰 자동 변환으로 들어간 둥근 따옴표를 `"`로 바꿉니다 |
| `말줄임표 '…' 대신 마침표 3개 '...'를 쓰세요` | `엄…`, `아… 줴줴이야…`의 `…`를 `...`로 바꿉니다 |

## 실행 중 에러

실행 중 에러는 일반 JS 에러와 같습니다. `hannam`과 Vite 플러그인은 소스맵을 함께 만들기 때문에 스택 트레이스가 `.hn` 원본의 줄을 가리킵니다.

```hn title="throw.hn"
티-원 할일추가(내용) {
  예? !내용.trim() {
    아... 줴줴이야... "빈 할 일"
  }
}

할일추가("  ")
```

```txt
throw.hn:3
    아... 줴줴이야... "빈 할 일"
     ^

Error: 빈 할 일
    at 할일추가 (throw.hn:3:5)
    at <anonymous> (throw.hn:7:1)
```

런타임 헬퍼 import를 파일 맨 끝에 붙이기 때문에, 변환된 JS의 줄 번호도 `.hn`과 같습니다. 소스맵이 없는 환경에서도 줄 위치는 맞습니다.

## 프로그램에서 에러 다루기

변환기 API를 직접 쓸 때 컴파일 에러는 `HannamSyntaxError`로 던져집니다.

| 속성 | 설명 |
| --- | --- |
| `line` | 줄 번호 (1부터) |
| `column` | 칸 번호 (0부터) |
| `filename` | 파일 이름 |
| `frame` | 코드 조각 |
| `message` | 위치와 코드 조각을 포함한 전체 메시지 |

`column`은 0부터 세고, 메시지 안의 `파일:줄:칸`은 1부터 센다는 점에 주의하세요.
