VS Code 확장은 `.mz` 파일을 `mz` 언어로 등록하고, 엠지스크립트 키워드를 칠하고, 컴파일 에러를 에디터에 바로 보여 줍니다.

## 제공하는 것

- **문법 하이라이팅**: 엠지스크립트 키워드마다 별도 scope를 붙이고, 키워드가 아닌 부분은 VS Code 내장 JavaScript 문법으로 칠합니다. 이 문서 사이트의 `.mz` 코드 블록도 같은 문법 파일로 칠했습니다.
- **컴파일 에러 표시**: 파일을 열거나 고치면 엠지스크립트 컴파일러로 검사해서, 에러는 빨간 밑줄로, 경고는 노란 밑줄로 보여 줍니다. 입력을 멈추고 0.25초 뒤에 다시 검사하고, 문제 패널(Problems)에도 같은 내용이 나옵니다. 에러가 여러 개라면 처음 만난 하나만 보여 줍니다. 컴파일러가 첫 에러에서 멈추기 때문입니다.
- **언어 설정**: `//`·`/* */` 주석 토글, 괄호 짝 맞추기, 자동 닫기, 들여쓰기
- **스니펫**: `예?`, `예???`, `요이~`, `티-원`, `티~원`, `진~지?` 등 17개. 엠지스크립트 키워드 접두어와 JS 키워드(`if`, `forof`, `function`, `try` …) 둘 다로 부를 수 있습니다.

자동 완성, 정의로 이동, 코드 서식 맞추기는 아직 없습니다. 확장은 편집만 돕고, 실행과 컴파일은 [`mz`와 `mzc`](/docs/getting-started/cli)가 맡습니다.

## 설치

확장은 마켓플레이스에 올라가 있지 않습니다. 저장소에서 `.vsix` 패키지를 만들어 설치합니다. [pnpm](https://pnpm.io)과 VS Code 1.90 이상이 필요합니다.

```sh
git clone https://github.com/keemtj/mzscript.git
cd mzscript
pnpm install
pnpm --filter @mzscript/core build
pnpm --filter mzscript-vscode package
code --install-extension packages/vscode/dist/mzscript-vscode.vsix
```

VS Code 확장 보기의 `...` 메뉴에서 **VSIX에서 설치...**를 골라도 됩니다. 지울 때는 다음 명령을 씁니다.

```sh
code --uninstall-extension mzscript.mzscript-vscode
```

## 색이 들어가는 방식

scope 이름은 `keyword.control.conditional.if.mz`, `storage.type.const.mz`처럼 JS 키워드와 같은 앞부분에 `.mz`를 붙인 형태입니다. 그래서 테마는 앞부분(`keyword.control`, `storage.type` 등)을 보고 엠지스크립트 키워드에 같은 역할의 JS 키워드와 같은 색을 입힙니다.

| 키워드 | scope |
| --- | --- |
| `엄` / `엄.` / `엄..` | `storage.type.var.mz` / `storage.type.let.mz` / `storage.type.const.mz` |
| `예?` / `예??` / `예???` | `keyword.control.conditional.if.mz` / `.else-if.mz` / `.switch.mz` |
| `요이~` / `요히~` / `요이이이~` | `keyword.control.loop.for-of.mz` / `.for-in.mz` / `.while.mz` |
| `티-원` / `티~원` | `storage.type.function.mz` / `storage.type.function.async.mz` |
| `무슨 발언이세요?` | `support.function.console.log.mz` |

## 한계

- TextMate 문법은 "문장 시작 위치"를 정확히 알 수 없습니다. 그래서 컴파일 에러가 나는 위치에 쓴 키워드도 칠해질 수 있습니다.
- 정해진 개수에서 벗어난 형태(`예????`, `아뇨아뇨`)는 칠하지 않습니다. 대신 컴파일 에러 표시가 밑줄로 알려 줍니다.
- 템플릿 `${}` 안의 값 위치 키워드는 템플릿 중첩 깊이 3까지만 칠합니다.
