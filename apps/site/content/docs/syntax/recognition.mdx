엠지스크립트는 일반 JS 코드와 겹치지 않도록 키워드를 알아보는 위치와 형태를 엄격하게 정해 두었습니다.

## 변환하지 않는 곳

- 문자열, 템플릿 리터럴, 주석, 정규식 안은 변환하지 않습니다. `"예? 진짜?"`는 그냥 글자입니다.
- 단, 템플릿 리터럴의 `${}` 안은 코드이므로 변환합니다. 여기에는 값 위치 키워드(`티~원!`, `예? 무슨 발언이세요?`)만 올 수 있고 문장 키워드는 올 수 없습니다.

```mz
무슨 발언이세요? `${티~원! 개수()}개`
```

```js
console.log(`${await 개수()}개`)
```

## 가장 긴 형태 우선

같은 위치에서 여러 키워드가 맞으면 가장 긴 형태를 먼저 고릅니다.

- `예? 무슨 발언이세요?` > `예???` > `예??` > `예?`
- `엄...` > `엄..` > `엄.` > `엄`
- `아뇨아뇨아뇨아뇨` > `아뇨`

## 문장 시작 위치

문장 키워드는 문장 시작 위치에서만 인식합니다. 문장 시작 위치는 다음과 같습니다.

- 파일 맨 앞, 줄의 첫 토큰(앞의 공백은 무시)
- `{` 바로 뒤, `}` 바로 뒤 (`} 예??`, `} 아뇨아뇨아뇨아뇨`, `} 지~랄`)
- `;` 바로 뒤
- `export`, `export default` 바로 뒤

그래서 `a ? b : c` 같은 삼항 연산자나 `티 - 원` 같은 뺄셈은 키워드로 읽지 않습니다.

## 일반 JS와 겹치는 경우

엠지스크립트 키워드가 없는 JS는 변환해도 출력이 입력과 한 글자도 다르지 않습니다. 고정 버전의 npm 패키지 파일 648개로 이 성질을 테스트합니다(`packages/core/test/superset.test.ts`).

올바른 JS인데 엠지스크립트에서 그대로 쓸 수 없는 경우는 두 가지입니다.

### 1. 문장 맨 앞이 키워드와 같은 글자로 시작할 때

이때는 키워드로 읽기 때문에 JS와 다르게 동작하거나 컴파일 에러가 납니다.

| JS 코드 | 엠지스크립트에서 |
| --- | --- |
| `아뇨 = 1` | `아뇨`(continue)로 읽고 에러를 냅니다 |
| `진~지` | `진~지?`(try)를 잘못 쓴 것으로 보고 에러를 냅니다 |

같은 이름이라도 문장 맨 앞이 아니면 일반 식별자입니다. `const 아뇨 = 1`, `엄 = 2`, `obj.엄`, `티-원`(뺄셈), `` `${엄}` ``은 모두 그대로 통과합니다.

### 2. ES 모듈에서 쓸 수 없는 코드

`.mz` 파일은 항상 ES 모듈로 실행됩니다. ES 모듈은 엄격 모드(strict mode)이므로, 변환 결과가 원본과 같더라도 다음 코드는 실행할 때 에러가 납니다.

- CommonJS: `require`, `module.exports`, `__dirname`, `__filename`
- 엄격 모드에서 막힌 문법: `with` 문, 선언하지 않은 변수에 대입하기, 8진수 리터럴(`010`) 등

이런 코드는 `import`, `export`, `import.meta.url`처럼 ES 모듈 방식으로 바꿔야 합니다. 옮기는 방법은 [JS에서 옮겨 오기](/docs/guides/from-javascript#commonjs는-es-모듈로-바꿉니다)에 있습니다.

## 값 위치

`티~원!`(await)과 `예? 무슨 발언이세요?`(confirm)는 값 위치에서도 인식합니다. 두 형태 모두 JS에서는 원래 문법 오류라서 일반 코드와 충돌하지 않습니다.

## 공백 경계

- `엄`, `엄.`, `엄..` 뒤에는 공백이 와야 합니다. `엄.length`는 `엄`이라는 변수의 멤버 접근입니다.
- `요이~`, `요히~`, `요이이이~`, `오호호호호~`, `오호호호홋~` 뒤에도 공백이 와야 키워드입니다.

## 헤더 자르기

`예?`, `예??`, `예???`, `요이~`, `요히~`, `요이이이~`의 헤더(조건·대상)는 **괄호 깊이 0에서 처음 나오는 `{` 직전까지**입니다.

- `()`, `[]` 안의 `{`는 무시합니다. 그래서 `예? 목록.some(x => { ... }) {`처럼 조건 안의 화살표 함수와 여러 줄 조건이 동작합니다.
- 헤더 맨 앞의 객체 리터럴은 괄호로 감싸야 합니다(`예? ({ a: 1 }).a {`).

## 둥근 따옴표와 말줄임표

휴대폰 키보드는 따옴표와 마침표를 자동으로 바꾸는 경우가 많습니다. 엠지스크립트는 JS와 같은 기준으로 처리합니다.

- **둥근 따옴표** `“ ” ‘ ’`: 문자열·주석 안에서는 그냥 글자이고, 코드에 나오면 컴파일 에러입니다. 에러 메시지가 일반 따옴표로 바꾸라고 위치와 함께 알려 줍니다.
- **말줄임표** `…`: 마침표 3개(`...`)와 다른 글자입니다. 키워드는 마침표만 인식하므로 `엄…`, `아… 줴줴이야…`처럼 코드에 `…`가 나오면 컴파일 에러입니다. 문자열·주석 안에서는 그대로 둡니다.

<Callout title="왜 자동으로 고쳐 주지 않나요?">
  처음에는 둥근 따옴표를 일반 따옴표로 바꿔 주는 방법도 검토했습니다. 그러면 `"“완료” 항목"`처럼 문자열 안의 UI 문구까지 바뀌어 깨집니다. JS와 같은 기준이 가장 예측하기 쉬워서, 대신 에러 메시지를 친절하게 만들었습니다.
