이미 짠 JavaScript를 처음부터 다시 쓸 필요는 없습니다. `hnc --from-js`에 파일이나 폴더를 넘기면 JS 키워드를 한남랭 키워드로 바꿔 줍니다. 설치 없이 해 보고 싶다면 [Playground](/playground)의 **JS 가져오기** 버튼에 코드를 붙여 넣으면 됩니다.

`hnc --from-js`는 `hannam-lang` 0.1.1부터 들어 있습니다.

## 어떻게 바뀌나요

```js title="greet.js"
function greet(hour) {
  if (hour < 12) {
    return "좋은 아침"
  } else {
    return "안녕하세요"
  }
}

for (const name of ["철수", "영희"]) {
  console.log(`${greet(9)}, ${name}`)
}
```

```hn title="greet.hn" migrate
티-원 greet(hour) {
  예? hour < 12 {
    아! 줴줴이야~ "좋은 아침"
  } 아뇨아뇨아뇨아뇨 {
    아! 줴줴이야~ "안녕하세요"
  }
}

요이~ name ["철수", "영희"] {
  무슨 발언이세요? `${greet(9)}, ${name}`
}
```

바뀌는 것은 키워드뿐입니다. 들여쓰기, 따옴표, 세미콜론, 줄바꿈 같은 서식은 원래 코드 그대로 남습니다.

## 의미는 그대로 지킵니다

바꾼 코드는 그 자리에서 다시 JS로 컴파일해서, 원래 코드와 구문 트리(AST)가 같은지 확인합니다. 다르게 나온 곳이 있으면 그 부분만 바꾸지 않고 JS 그대로 둡니다. 한남랭은 JS의 상위 집합이라, JS 그대로 남은 부분도 올바른 `.hn` 코드입니다.

그래서 "바꿀 수 있는 만큼만" 바꿉니다. 바꾸지 않은 곳은 위치와 이유를 함께 알려 줍니다.

## 사용법

```sh
npm i -D hannam-lang
npx hnc --from-js src          # 바뀔 내용만 보여 줍니다
npx hnc --from-js src --write  # 원본 옆에 .hn 파일을 만듭니다
```

| 옵션 | 설명 |
| --- | --- |
| `--from-js` | `.js`, `.mjs` 파일을 한남랭으로 바꿉니다. 이 옵션만 주면 파일을 만들지 않고 바뀔 내용만 보여 줍니다 |
| `--write` | 원본 옆에 같은 이름의 `.hn` 파일을 만듭니다. 원본 `.js`는 그대로 두니, 확인한 뒤 직접 지우세요. 이미 있는 `.hn`은 덮어쓰지 않습니다 |
| `--comments` | 줄 맨 앞의 `//` 주석도 `엄...`으로 바꿉니다. `// eslint-disable`처럼 도구가 읽는 주석은 그대로 둡니다 |

- 폴더를 주면 그 안의 `.js`, `.mjs`를 모두 찾습니다. `node_modules`, 점으로 시작하는 폴더, `*.min.js`, `.gitignore`에 든 파일은 뺍니다.
- 함께 옮기는 파일을 가리키는 상대 경로 import는 `.hn`으로 바꿉니다(`"./store.js"` → `"./store.hn"`). 함께 옮기지 않는 파일과 패키지 이름은 그대로 둡니다.
- 옮기지 못한 파일(CommonJS, 압축 파일, 이미 `.hn`이 있는 파일)을 가리키는 import는 `.js` 그대로 둡니다.
- `.mjs`에서 옮긴 `.hn`도 `hnc`로 컴파일하면 `.js`가 됩니다. Node에서 실행한다면 `package.json`에 `"type": "module"`이 있어야 합니다.
- `require`, `module.exports`를 쓰는 CommonJS 파일은 `.hn`에서 실행되지 않아 건너뜁니다. [ES 모듈로 바꾼 뒤](/docs/guides/from-javascript#commonjs는-es-모듈로-바꿉니다) 다시 실행하세요.

## 바꾸는 것과 그대로 두는 것

| 바꾸는 것 | 조건 |
| --- | --- |
| `var` · `let` · `const`, `if` · `else`, `while`, `break` · `continue`, `return`, `function` · `async function` 선언, `class` · `extends` 선언, `try` · `catch` | 문장 맨 앞일 때. `if`와 `while`은 본문이 블록(`{ }`)이어야 하고, `break`와 `continue`는 레이블이 없어야 합니다 |
| `await` | 어디서나 (`for await`는 제외) |
| 문장으로 쓴 `console.log(…)` | 한 줄에 다 쓴 경우. `console`이 지역 변수로 가려지지 않았을 때 |
| `confirm(…)`, `window.confirm(…)` | 전역 `confirm`이고 인자가 있을 때 |
| `for (const x of 목록)`, `for (const k in 객체)` | 반복 변수를 `const`로 선언했을 때 (`요이~`, `요히~`는 `const`로 컴파일됩니다) |
| `for (let i = a; i < b; i++)` | 정확히 이 모양일 때 (`요이~ i a..b`) |
| `switch` | 모든 `case`가 `break`, `return`, `throw`, `continue`로 끝나고 `default`가 마지막일 때. case 조건이 case 안에서 선언한 이름을 쓰면 바꾸지 않습니다(조건이 블록 밖으로 나가 가리키는 대상이 달라지기 때문입니다) |
| `throw new X(…)` | `new`로 만든 값을 던질 때 |

이런 코드는 바꾸지 않고 JS 그대로 둡니다.

- 대응하는 키워드가 없는 문법: `do...while`, 레이블 문, `for await`, 제너레이터, 화살표 함수, 메서드, 함수·클래스 표현식, `finally`
- 중괄호 없는 `if (a) b()`
- `throw "문자열"`, `throw 에러`: 한남랭에서는 [항상 Error로 감싸서](/docs/syntax/functions#throw는-항상-error를-던집니다) 동작이 달라지기 때문입니다.
- 여러 줄에 걸친 `console.log(…)`
- `/* */` 블록 주석과 JSDoc
- `__hn`으로 시작하는 이름이 있는 파일의 `switch`와 `confirm`: 컴파일러가 만드는 이름과 겹칠 수 있기 때문입니다.

## 옮기기 전에 알아 둘 것

- **서식은 옮기기 전에 정리하세요.** Prettier, ESLint, Biome은 `.hn`을 읽지 못합니다. 옮긴 파일에서는 지금 쓰는 formatter와 linter를 쓸 수 없습니다.
- **문장 맨 앞에 키워드와 같은 이름이 있으면 옮길 수 없습니다.** 예를 들어 변수 `아뇨`에 값을 대입하는 문장은 한남랭에서 `continue`로 읽힙니다. 이런 파일은 이름을 바꾸라는 메시지와 함께 건너뜁니다. 자세한 내용은 [인식 규칙](/docs/syntax/recognition#일반-js와-겹치는-경우)에 있습니다.
- TypeScript와 JSX는 아직 지원하지 않습니다.

## 코드에서 부르기

```js
import { migrate, MigrateError } from "hannam-lang/migrate"

try {
  const { code, changes, skipped } = migrate(source, { filename: "app.js" })
} catch (e) {
  if (e instanceof MigrateError) {
    console.error(e.message) // 파일째 옮길 수 없는 이유
  }
}
```

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `filename` | 없음 | 에러 메시지에 쓸 파일 이름 |
| `comments` | `false` | 줄 맨 앞의 `//` 주석을 `엄...`으로 바꿀지 여부 |
| `allowCommonJS` | `false` | CommonJS 파일도 바꿀지 여부 |
| `rewriteImport` | 없음 | import 경로를 받아 새 경로를 돌려주는 함수. `undefined`를 돌려주면 그대로 둡니다 |

`skipped`에는 바꾸지 않은 곳이 `{ line, column, kind, reason }` 모양으로 들어 있습니다.
