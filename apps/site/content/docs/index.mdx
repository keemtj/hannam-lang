엠지스크립트(mzscript)는 말투만 바꿔 쓰는 JavaScript입니다. `.mz` 파일에 `if` 대신 `예?`, `console.log` 대신 `무슨 발언이세요?`처럼 쓰면 컴파일러가 JavaScript로 바꿔 줍니다. 바뀌는 것은 문장 맨 앞의 키워드뿐이고 나머지는 JS 그대로 통과하므로, 변환된 코드는 브라우저와 Node 어디서든 그대로 실행됩니다.

```mz title="hello.mz"
엄.. 할일들 = ["장보기", "빨래"]

요이~ 할일 할일들 {
  무슨 발언이세요? `할 일: ${할일}`
}
```

```js title="hello.js"
const 할일들 = ["장보기", "빨래"]

for (const 할일 of 할일들) {
  console.log(`할 일: ${할일}`)
}
```

## 새 언어가 아니라 JavaScript의 말투

엠지스크립트에는 새로운 타입이나 실행 규칙이 없습니다. 변수, 스코프, 비동기, 모듈은 모두 JavaScript의 것을 그대로 씁니다. 엠지스크립트가 바꾸는 것은 코드를 **읽고 쓰는 말투**뿐입니다.

- **JS 상위 호환**: 키워드가 없는 JS는 변환해도 한 글자도 바뀌지 않습니다. 다만 [예외가 두 가지](/docs/syntax/recognition#일반-js와-겹치는-경우) 있습니다. 문장 맨 앞이 엠지스크립트 키워드와 같은 글자로 시작하는 경우, 그리고 출력이 ES 모듈이라 CommonJS나 엄격 모드(strict mode)에서 막힌 문법을 쓰는 경우입니다. ES2015 이후 문법, DOM, `fetch`, Node 생태계는 모두 그대로 씁니다.
- **브라우저와 Node 양쪽**: 출력은 ES 모듈이고, 런타임 헬퍼가 필요한 경우에만 작은 모듈 하나를 가져옵니다.
- **도구**: CLI(`mz`, `mzc`), Vite 플러그인, VS Code 확장, 웹 Playground가 있습니다.
- **에러 위치**: 소스맵을 함께 만들기 때문에 에러 스택이 `.mz` 원본의 줄을 가리킵니다.

엠지스크립트는 읽기에는 낯설어도 **웹 개발에 실제로 쓸 수 있는 것**을 목표로 합니다. 프론트엔드와 서버를 모두 `.mz`로 짠 [투두 풀스택 앱](/docs/guides/todo-fullstack)이 그 예입니다.

### CoffeeScript와 다른 점

CoffeeScript도 JavaScript로 컴파일되지만, 목적은 JS를 더 짧고 편하게 쓰는 것이었습니다. 그래서 화살표 함수, 클래스, 템플릿 문자열처럼 CoffeeScript가 먼저 제공하던 편의 기능이 JS 표준에 들어가자 쓸 이유가 줄었습니다.

엠지스크립트가 바꾸는 것은 편의가 아니라 말투입니다. JS가 발전해도 `if`를 `예?`로 쓰는 기능은 표준에 들어가지 않습니다. 또 엠지스크립트는 키워드가 아닌 부분을 해석하지 않고 넘기므로, JS에 새 문법이 생겨도 대부분 엠지스크립트에서 바로 쓸 수 있습니다.

## 키워드 한눈에 보기

각 키워드가 어떻게 변환되는지는 [문법 레퍼런스](/docs/syntax)에 정리했습니다.

| 엠지스크립트 | JS |
| --- | --- |
| `엄` `엄.` `엄..` `엄...` | `var` `let` `const` `// 주석` |
| `예?` `예??` `예???` | `if` `else if` `switch` |
| `아뇨아뇨아뇨아뇨` | `else`, `default` |
| `요이~` `요이이이~` | `for...of`·범위 반복, `while` |
| `요히~` | `for...in` |
| `줴줴이야` / `아뇨` | `break` / `continue` |
| `아! 줴줴이야~` / `아... 줴줴이야...` | `return` / `throw` |
| `티-원` `티~원` `티~원!` | `function` `async function` `await` |
| `진~지?` / `지~랄` | `try` / `catch` |
| `오호호호호~` `오호호호홋~` | `class` `class extends` |
| `무슨 발언이세요? 값` | `console.log` |
| `예? 무슨 발언이세요?(질문)` | `confirm` |

## 설계 원칙

엠지스크립트의 문법은 다음 원칙에 따라 정했습니다.

### 한 형태 = 한 문법

키워드의 변형(점·물음표·글자 개수, `~`·`!` 유무)은 각각 다른 문법입니다. 같은 뜻의 별칭은 두지 않습니다. 그래서 `예?`(if), `예??`(else if), `예???`(switch)는 모두 다른 문법이고, `아뇨`(continue)와 `아뇨아뇨아뇨아뇨`(else)도 다른 문법입니다. 정해진 개수에서 벗어난 형태(`예????`, `아뇨아뇨`)는 조용히 통과시키지 않고 컴파일 에러로 알려 줍니다.

### 설탕만 두고 별칭은 두지 않는다

자주 쓰는데 길고 보기 싫은 패턴은 짧은 키워드로 감쌉니다. 예를 들어 `아... 줴줴이야... "빈 할 일"`은 `throw new Error("빈 할 일")`이 됩니다. 반대로 `!` 같은 한 글자 연산자를 긴 키워드로 바꾸는 별칭은 만들지 않습니다. 읽기만 어려워지기 때문입니다.

### 문장 맨 앞 키워드만 바꾼다

설탕은 `if`, `for`, `function`처럼 **문장 맨 앞에 오는 키워드**에만 적용합니다. 연산자, `new`, `typeof`, `this`, 화살표 함수 같은 값 위치 문법은 JS 그대로 씁니다.

### 플랫폼 API는 JS 그대로

TypeScript가 DOM 이름을 바꾸지 않는 것처럼 `fetch`, `document.querySelector` 같은 API 이름은 그대로 둡니다. 자주 쓰는 `console.log`와 `confirm`만 예외로 엠지스크립트 키워드를 둡니다.
