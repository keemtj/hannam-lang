title: 한남랭 소개
description: 한남 말투 밈 11개로 쓰는 JS 상위 호환 언어입니다.
---

한남랭(hannam-lang)은 `.hn` 파일에 한남 말투 밈으로 코드를 쓰면 JavaScript로 바꿔 주는 언어입니다. 밈 키워드만 JS로 바뀌고 나머지는 JS 그대로 통과하므로, 변환된 코드는 브라우저와 Node 어디서든 그대로 실행됩니다.

```hn title="hello.hn"
엄.. 할일들 = ["장보기", "빨래"]

요이~ 할일 할일들 {
  무슨 발언이세요? `할 일: ${할일}`
}
```

```js title="hello.js"
const 할일들 = ["장보기", "빨래"]

for (const 할일 of 할일들) {
  console.log(`할 일: ${할일}`)
}
```

## 장난 언어가 아니라 쓸 수 있는 언어

원조 밈 언어인 [엄랭(rycont/umjunsik-lang)](https://github.com/rycont/umjunsik-lang)은 정수와 goto만으로 프로그램을 짜는 퍼즐에 가깝습니다. 한남랭은 그 "시즌2"를 목표로, **웹 개발에 실제로 쓸 수 있는 언어**를 지향합니다.

- **JS 상위 호환**: 올바른 JS 코드는 대부분 그대로 올바른 한남랭 코드입니다. ES2015 이후 문법, DOM, `fetch`, Node 생태계를 모두 그대로 씁니다.
- **브라우저와 Node 양쪽**: 출력은 ES 모듈이고, 런타임 헬퍼가 필요한 경우에만 작은 모듈 하나를 가져옵니다.
- **도구**: CLI(`hannam`, `hannamc`), Vite 플러그인, VS Code 확장, 웹 Playground가 있습니다.
- **에러 위치**: 소스맵을 함께 만들기 때문에 에러 스택이 `.hn` 원본의 줄을 가리킵니다.

최종 목표 데모는 프론트엔드와 서버를 모두 `.hn`으로 짠 풀스택 투두 앱입니다. [투두 풀스택 만들기](/docs/guides/todo-fullstack)에서 전체 코드를 볼 수 있습니다.

## 밈 11개

이번 버전은 한남 말투 밈 11개만 씁니다. 각 밈이 어떤 문법이 되는지는 [문법 레퍼런스](/docs/syntax)에 정리했습니다.

| 밈 | 문법 |
| --- | --- |
| `엄` `엄.` `엄..` `엄...` | `var` `let` `const` `// 주석` |
| `예?` `예??` `예???` | `if` `else if` `switch` |
| `아뇨아뇨아뇨아뇨` | `else`, `default` |
| `요이~` `요이이이~` | `for...of`·범위 반복, `while` |
| `요히~` | `for...in` |
| `줴줴이야` / `아뇨` | `break` / `continue` |
| `아! 줴줴이야~` / `아... 줴줴이야...` | `return` / `throw` |
| `티-원` `티~원` `티~원!` | `function` `async function` `await` |
| `진~지?` / `지~랄` | `try` / `catch` |
| `오호호호호~` `오호호호홋~` | `class` `class extends` |
| `무슨 발언이세요?` | `console.log`, `confirm` |

## 설계 원칙

한남랭의 문법은 다음 원칙에 따라 정했습니다.

### 한 형태 = 한 문법

밈의 변형(점·물음표·글자 개수, `~`·`!` 유무)은 각각 다른 문법입니다. 같은 뜻의 별칭은 두지 않습니다. 그래서 `예?`(if), `예??`(else if), `예???`(switch)는 모두 다른 문법이고, `아뇨`(continue)와 `아뇨아뇨아뇨아뇨`(else)도 다른 문법입니다. 정해진 개수에서 벗어난 형태(`예????`, `아뇨아뇨`)는 조용히 통과시키지 않고 컴파일 에러로 알려 줍니다.

### 설탕만 두고 별칭은 두지 않는다

자주 쓰는데 길고 보기 싫은 패턴은 짧은 밈으로 감쌉니다. 예를 들어 `아... 줴줴이야... "빈 할 일"`은 `throw new Error("빈 할 일")`이 됩니다. 반대로 `!` 같은 한 글자 연산자를 긴 밈으로 바꾸는 별칭은 만들지 않습니다. 읽기만 어려워지기 때문입니다.

### 문장 맨 앞 키워드만 밈으로

설탕은 `if`, `for`, `function`처럼 **문장 맨 앞에 오는 키워드**에만 적용합니다. 연산자, `new`, `typeof`, `this`, 화살표 함수 같은 값 위치 문법은 JS 그대로 씁니다.

### 플랫폼 API는 JS 그대로

TypeScript가 DOM 이름을 바꾸지 않는 것처럼 `fetch`, `document.querySelector` 같은 API 이름은 그대로 둡니다. 자주 쓰는 `console.log`와 `confirm`만 예외로 밈을 둡니다.
