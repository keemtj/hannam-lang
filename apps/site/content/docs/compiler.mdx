한남랭 컴파일러는 JavaScript 전체를 파싱해서 구문 트리(AST)를 만들지 않습니다. 정규식으로 글자를 치환하지도 않습니다. **JS 토큰을 나누는 렉서 위에서 문장이 시작하는 위치만 골라 키워드를 알아보고, 원문을 그 자리에서 고치는 방식**입니다.

## 세 단계

| 단계 | 파일 | 하는 일 |
| --- | --- | --- |
| 렉서 | `packages/core/src/lexer.ts` | JS 토큰의 경계를 나눕니다. 문자열, 중첩된 템플릿 리터럴, 주석, 정규식을 구분하고, `/`가 나눗셈인지 정규식의 시작인지 앞 토큰을 보고 판단합니다. 키워드는 알아보지 않습니다 |
| 변환기 | `packages/core/src/compile.ts` | 토큰을 따라가며 괄호와 블록의 스택을 관리합니다. 이 스택으로 지금 위치가 블록인지, 객체 리터럴인지, 클래스 본문인지, 템플릿의 `${}` 안인지 판단하고, 문장 시작 위치에서만 한남랭 키워드를 찾습니다. 키워드마다 처리 함수가 따로 있어 형태를 검사하고, 틀리면 위치가 담긴 컴파일 에러를 냅니다 |
| 출력 | [magic-string](https://github.com/Rich-Harris/magic-string) | 구문 트리를 다시 출력하지 않고, 원문 문자열에서 키워드 자리만 바꿉니다. 그래서 들여쓰기, 주석, 줄 번호가 그대로 남고 소스맵도 정확합니다 |

```hn title="입력"
예? 할일.완료 {
  아뇨
}
```

```js title="출력"
if (할일.완료) {
  continue
}
```

위 예에서 바뀐 것은 `예?` → `if (`, 줄 끝의 `)` 추가, `아뇨` → `continue`뿐입니다. `할일.완료`와 공백, 중괄호는 원문의 글자 그대로입니다.

## 구문 트리를 만들지 않는 이유

한남랭의 핵심 약속은 **JS를 그대로 통과시키는 것**입니다. 원문을 직접 고치는 방식은 이 약속을 지키기 쉽습니다.

- **키워드가 없는 JS는 한 글자도 바뀌지 않습니다.** 고칠 자리가 없으면 원문이 그대로 출력되기 때문입니다. 구문 트리를 다시 출력하면 따옴표, 괄호, 공백 같은 모양이 달라질 수 있습니다.
- **JS의 새 문법을 따로 지원하지 않아도 됩니다.** 키워드가 아닌 부분은 해석하지 않고 넘기므로, JS에 새 문법이 생겨도 대부분 바로 쓸 수 있습니다.
- **출력이 원본과 거의 같은 모양입니다.** 변환된 JS를 직접 읽거나 디버깅하기 쉽습니다.

## 대신 감수하는 것

"이 `{`는 블록인가, 객체 리터럴인가", "이 문장은 어디서 끝나는가" 같은 판단을 JS 문법 전체가 아니라 규칙의 집합으로 합니다. JS에는 자동 세미콜론 삽입(ASI), 정규식과 나눗셈의 구분, 템플릿 안의 표현식처럼 문맥에 따라 뜻이 달라지는 문법이 많아서, 이 판단이 컴파일러에서 가장 까다로운 부분입니다.

그래서 문맥 판단은 테스트로 지킵니다. 지금까지 찾은 경우는 모두 회귀 테스트(`packages/core/test/regressions.test.ts`)로 고정했습니다.

- 객체 리터럴의 키와 블록 안의 문장
- 화살표 함수가 돌려주는 `({ })`
- 후위 증감(`i++`)과 프로퍼티 이름(`obj.of`) 뒤의 `/`
- 클래스 본문과 `static {}` 블록
- 여러 줄에 걸친 값과 줄 끝의 삼항 연산자

## 완성도의 기준

컴파일러가 올바른지는 다음 세 가지로 봅니다.

1. **의미 보존**: 한남랭 키워드가 없는 올바른 JS는 변환해도 의미가 같아야 합니다. 이 저장소는 더 강한 조건인 "출력이 입력과 한 글자도 다르지 않다"를 검사합니다. 고정 버전의 npm 패키지(acorn, magic-string, lodash-es) 파일 648개를 넣고 확인합니다(`packages/core/test/superset.test.ts`). 출력이 올바른 JS인지만 보는 것보다 강한 조건입니다. 글자가 같으면 의미도 같기 때문입니다.
2. **문맥 정확성**: 키워드는 문법상 허용된 위치에서만 바뀌어야 합니다. 문자열, 주석, 정규식, 객체 키, 프로퍼티 이름 안의 같은 글자는 건드리지 않습니다. [인식 규칙](/docs/syntax/recognition)에 정리했습니다.
3. **진단 정확성**: 틀린 형태를 쓰면 정확한 위치와 고칠 방법을 알려 줘야 합니다. 에러마다 기대하는 메시지와 줄 번호를 테스트합니다(`packages/core/test/errors.test.ts`). 코드 조각의 `^` 표시는 한글을 두 칸으로 세어 위치를 맞춥니다.

## 직접 살펴보기

- 키워드 하나가 어떻게 바뀌는지 보려면 [Playground](/playground)에서 코드를 쓰고 오른쪽의 JS를 봅니다.
- 변환기에 새 키워드를 넣는 방법과 기준은 [기여하기](/docs/contributing)를 봅니다.
- 문법 판단의 기준이 되는 명세는 저장소의 `docs/hannam-lang-syntax.md`입니다.
