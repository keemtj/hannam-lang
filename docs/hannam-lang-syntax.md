# hannam-lang 문법 정리

## 설계 원칙
- **한 형태 = 한 문법.** 밈의 변형(점·물음표·글자 개수, `~`·`!` 유무)은 각각 다른 문법이어야 하며, 같은 뜻의 별칭은 두지 않는다.
  - 개수가 다르면 다른 문법: `예?` ≠ `예??` ≠ `예???`, `아뇨` ≠ `아뇨아뇨아뇨아뇨`
- **설탕만 두고 별칭은 두지 않는다.** JS 기호 하나를 긴 밈으로 바꾸는 것(예: `!` → `아뇨아뇨아뇨아뇨!`)은 설탕이 아니다.
- **플랫폼 API는 JS 그대로.** `fetch`, DOM 등은 이름을 바꾸지 않는다. 자주 쓰는 `console.log`, `confirm`만 예외로 설탕을 둔다.
- **둥근 따옴표와 `…`는 JS와 같은 기준으로 처리한다.** 문자열·주석 안에서는 그냥 글자이고, 코드에 나오면 컴파일 에러 (아래 인식 규칙 참고)

## 설탕 적용 범위
JS 전체를 옮기지 않는다. **문장 맨 앞에 오는 키워드만** 설탕 대상으로 삼고, 연산자·`new`·`typeof`·`this`·화살표 함수 같은 값 위치 문법은 JS 그대로 둔다.

판단 기준: 투두 풀스택 데모에서 자주 쓰는가 + 밈 뉘앙스가 역할과 맞는가

| 판단 | 키워드 |
| --- | --- |
| 밈 있음 | `var` `let` `const` `if` `else` `switch` `for` `while` `break` `continue` `function` `async` `await` `return` `throw` `try` `catch` `class` `extends`, 플랫폼 API 중 `console.log` `confirm` |
| JS 그대로 | `finally` `do...while` `for await` `yield` `function*` `label:` `debugger` `with`, 모든 연산자·표현식, 플랫폼 API |
| 다음 버전 후보 (일반 밈, 지금은 JS 그대로) | `import` `export` `true` `false` |

## 기본 규칙
- 블록은 JS처럼 중괄호 `{ }`
- 조건 괄호는 선택 (`예? 조건 {`, `예? (조건) {` 둘 다 가능)
- 세미콜론 생략
- 설탕이 있는 문법은 설탕을 우선 사용, 밈에 없는 문법·API만 JS 그대로
- 출력은 ESM (함수 밖 `티~원!` 사용 가능)
- **문장 키워드는 띄어 쓰고, 값 위치 함수는 괄호를 붙인다.** `무슨 발언이세요? 값`, `아! 줴줴이야~ 값`처럼 문장 키워드는 "키워드 + 공백 + 값"이고, `예? 무슨 발언이세요?("질문")`처럼 값을 돌려주는 설탕은 함수 호출 형태. JS에서 `return x`와 `confirm(x)`의 모양이 다른 것과 같음 (`티~원!`은 JS `await`처럼 값 위치에서도 띄어 쓰는 예외)

## 변수 · 주석 (엄 가족)
| 한남랭 | JS |
| --- | --- |
| `엄 이름 = 값` | `var` |
| `엄. 이름 = 값` | `let` |
| `엄.. 이름 = 값` | `const` |
| `엄... 내용` | `// 주석` (문장 맨 앞, 클래스 본문·객체·괄호 안의 줄 맨 앞) |

- 엄 뒤에는 반드시 공백 + 식별자 또는 구조분해 패턴이 온다. `엄 = 1`, `엄.length`처럼 `엄`이라는 변수를 쓰는 일반 JS와 구분하기 위함
- 구조분해 지원: `엄.. { 내용, 완료 } = 할일`, `엄.. [첫째, ...나머지] = 목록`

```
엄... 할 일 목록
엄.. 할일들 = []
엄. 개수 = 0
엄 전역설정 = null
```
```js
// 할 일 목록
const 할일들 = []
let 개수 = 0
var 전역설정 = null
```

## 조건문 (예 가족)
| 한남랭 | JS |
| --- | --- |
| `예? 조건 {` | `if` |
| `} 예?? 조건 {` | `else if` |
| `} 아뇨아뇨아뇨아뇨 {` | `else` |
| `예??? 값 {` | `switch` (아래 참고) |

- `아뇨아뇨아뇨아뇨`는 정확히 4회 반복 (2·3·5회 등은 에러, 1회는 `continue`)
- `예??`는 `예?` 체인의 `}` 바로 뒤에서만 인식. 단독으로 쓰면 에러
- 물음표는 1~3개만 허용. `예????`처럼 4개 이상이면 **컴파일 에러** (JS로 통과시키지 않음)
- 정해진 개수에서 벗어난 밈 변형(`아뇨아뇨`, `요이이~`, `오호호~` 등)은 모두 같은 원칙으로 컴파일 에러. 통과시키면 JS 파서가 엉뚱한 위치에서 알아보기 어려운 에러를 내기 때문

```
예? 개수 === 0 {
  무슨 발언이세요? "할 일 없음"
} 예?? 개수 < 5 {
  무슨 발언이세요? "여유 있음"
} 아뇨아뇨아뇨아뇨 {
  무슨 발언이세요? "바쁨"
}
```
```js
if (개수 === 0) {
  console.log("할 일 없음")
} else if (개수 < 5) {
  console.log("여유 있음")
} else {
  console.log("바쁨")
}
```

### switch: `예???`
```
예??? 필터 {
  "전체" {
    보여줄것 = 할일들
  }
  "완료", "보관" {
    보여줄것 = 할일들.filter(할일 => 할일.완료)
  }
  아뇨아뇨아뇨아뇨 {
    보여줄것 = 할일들.filter(할일 => !할일.완료)
  }
}
```
```js
{ const __hn_s0 = 필터;
  if (__hn_s0 === "전체") {
    보여줄것 = 할일들
  }
  else if (__hn_s0 === "완료" || __hn_s0 === "보관") {
    보여줄것 = 할일들.filter(할일 => 할일.완료)
  }
  else {
    보여줄것 = 할일들.filter(할일 => !할일.완료)
  }
}
```

- `case` 키워드 없음. `예???` 블록 바로 안에서는 `값 {` 형태가 갈래 하나
- 값 여러 개는 쉼표로 묶음 → fallthrough 없음, `break` 불필요
- 비교는 `===` (JS switch와 동일), 대상 값은 한 번만 평가
- 갈래 값에 연산자가 있으면 괄호로 감싸서 JS의 `case`와 같게 비교 (`1 || 5 {` → `__hn_s0 === (1 || 5)`). 식별자·리터럴·`a.b` 멤버 접근은 그대로
- 비교할 대상 값은 하나만 씀 (`예??? a, b {`는 에러). 갈래 사이에 `;`를 쓰지 않음
- `default`는 `아뇨아뇨아뇨아뇨` (else와 같은 의미라 재사용). 반드시 마지막 갈래
- **JS `switch`가 아니라 if-else 체인으로 변환.** 그래서 갈래 안의 `줴줴이야`·`아뇨`는 바깥 반복문에 작동함 (JS switch로 변환하면 switch만 빠져나가 예상과 다르게 동작)
- 전체를 `{ }` 블록으로 감싸서 임시 변수가 바깥으로 새지 않게 함. 임시 변수 이름은 파일 안에서 순서대로 `__hn_s0`, `__hn_s1` …

## 반복문 (요이 가족)
| 한남랭 | JS |
| --- | --- |
| `요이~ 항목 목록 {` | `for (const 항목 of 목록)` |
| `요이~ i 0..10 {` | `for (let i = 0; i < 10; i++)` (끝 미포함) |
| `요히~ 키 객체 {` | `for (const 키 in 객체)` |
| `요이이이~ 조건 {` | `while (조건)` |
| `줴줴이야` | `break` |
| `아뇨` | `continue` |

- `요이이이~`의 `이`는 정확히 3개 (`요이이~`, `요이이이이~` 등은 에러)
- 물결 없는 `요이`, `요히`는 예약 (메서드 설탕 후보, 미정 참고)
- `요이~`·`요히~` 헤더는 첫 패턴 = 루프 변수, 나머지 = 대상 식. 구조분해 패턴 가능
- `줴줴이야`, `아뇨`는 홀로 한 문장을 이루므로 예약어로 취급 (같은 이름의 변수 사용 불가)
- `do...while`, `for await`는 JS 그대로

### for...of
```
요이~ 할일 할일들 {
  예? 할일.완료 {
    아뇨
  }
  무슨 발언이세요? 할일.내용
}
```
```js
for (const 할일 of 할일들) {
  if (할일.완료) {
    continue
  }
  console.log(할일.내용)
}
```

### 범위
```
요이~ i 0..할일들.length {
  무슨 발언이세요? `${i + 1}. ${할일들[i].내용}`
}
```
```js
for (let i = 0; i < 할일들.length; i++) {
  console.log(`${i + 1}. ${할일들[i].내용}`)
}
```

### for...in
```
엄.. 설정 = { 테마: "다크", 정렬: "최신순" }
요히~ 키 설정 {
  무슨 발언이세요? `${키}: ${설정[키]}`
}
```
```js
const 설정 = { 테마: "다크", 정렬: "최신순" }
for (const 키 in 설정) {
  console.log(`${키}: ${설정[키]}`)
}
```

### 구조분해
```
요이~ [키, 값] Object.entries(설정) {
  무슨 발언이세요? `${키}=${값}`
}
```
```js
for (const [키, 값] of Object.entries(설정)) {
  console.log(`${키}=${값}`)
}
```

### while

엄. 남은수 = 3
요이이이~ 남은수 > 0 {

## 함수 (티원 · 줴줴이야)
| 한남랭 | JS |
| --- | --- |
| `티-원 이름(인자) {` | `function` |
| `티~원 이름(인자) {` | `async function` |
| `티~원! 표현식` | `await` |
| `아! 줴줴이야~ 값` | `return` (값 생략 가능) |
| `아... 줴줴이야... 값` | `throw` (문자열이면 Error로 자동 감쌈) |

- `아! 줴줴이야~`, `아... 줴줴이야...`의 값은 **같은 줄**에 있어야 함 (JS `return`의 ASI 규칙과 동일). 줄바꿈 뒤 값은 다음 문장으로 취급
- 한 줄 블록에서는 같은 줄의 `}` 앞에서 값이 끝남 (`예? !항목 { 아! 줴줴이야~ }`, `"전체" { 아! 줴줴이야~ 할일들 }`)
- 화살표 함수, async 화살표, 메서드는 JS 그대로

### throw 변환 규칙
문자열을 그대로 던지지 않고 항상 Error 객체를 던진다 (`throw new Error` 설탕).

| 한남랭 | JS |
| --- | --- |
| `아... 줴줴이야... "빈 할 일"` | `throw new Error("빈 할 일")` |
| `` 아... 줴줴이야... `${id}번 없음` `` | ``throw new Error(`${id}번 없음`)`` |
| `아... 줴줴이야... 에러` (변수 등 타입을 모르는 값) | `throw __hn.toError(에러)` |
| `아... 줴줴이야... new 검증에러("...")` | `throw new 검증에러("...")` (그대로) |

- 문자열·템플릿 리터럴은 컴파일 시점에 `new Error(...)`로 직접 변환 (런타임 헬퍼 불필요, 스택 트레이스에 헬퍼가 끼지 않음)
- 타입을 모르는 값만 런타임 `__hn.toError`: 문자열이면 `new Error(값)`, 그 외(Error 객체 등)는 그대로

### 함수 + return + throw
```
티-원 할일추가(내용) {
  예? !내용.trim() {
    아... 줴줴이야... "빈 할 일"
  }
  할일들.push({ id: Date.now(), 내용, 완료: false })
  아! 줴줴이야~ 할일들.length
}
```

function 할일추가(내용) {
  if (!내용.trim()) {
    throw new Error("빈 할 일")
  }
  할일들.push({ id: Date.now(), 내용, 완료: false })
  return 할일들.length
}
```

### 값 없는 return (가드)

티-원 삭제(id) {
  예? !id {
    아! 줴줴이야~
  }
  할일들.splice(할일들.findIndex(할일 => 할일.id === id), 1)

```

function 삭제(id) {

  }

### async + await
```
티~원 불러오기(url) {
  엄.. 응답 = 티~원! fetch(url)
  예? !응답.ok {
    아... 줴줴이야... "불러오기 실패"
  }
  아! 줴줴이야~ 티~원! 응답.json()
}
```
```js
async function 불러오기(url) {
  const 응답 = await fetch(url)
  if (!응답.ok) {
    throw new Error("불러오기 실패")
  }
  return await 응답.json()
}
```

## 예외 처리 (진지 · 지랄)
| 한남랭 | JS |
| --- | --- |
| `진~지? {` | `try` |
| `} 지~랄 e {` | `catch (e)` |
| `} 지~랄 {` | `catch` (에러 변수 생략, ES2019) |

- 뉘앙스: `진~지?`로 진지하게 시도해 보고, 누가 `아... 줴줴이야...`로 던지면 `지~랄`("아 진짜?")로 받아 준다
- 에러 변수의 괄호는 선택 (`} 지~랄 e {`, `} 지~랄 (e) {` 둘 다 가능)
- 구조분해도 가능 (`} 지~랄 { message } {` → `} catch ({ message }) {`). `{ ... }` 뒤에 `{`가 한 번 더 오면 앞쪽을 에러 변수로 봄
- `지~랄`은 `진~지?` 블록의 `}` 바로 뒤에서만 인식
- `finally`는 JS 그대로 (`} finally {`)
- 형태 고정: `지랄`, `지-랄`, `진지?`, `진~지`(물음표 없음)는 에러
- JS와 충돌 없음: `~`는 단항 연산자라 `지~랄`, `진~지`는 JS에서 원래 문법 오류

```
진~지? {
  엄.. 할일들 = 티~원! 불러오기("/api/todos")
  무슨 발언이세요? `${할일들.length}개 불러옴`
} 지~랄 e {
  무슨 발언이세요? e.message
} finally {
  로딩중 = false
}
```
```js
try {
  const 할일들 = await 불러오기("/api/todos")
  console.log(`${할일들.length}개 불러옴`)
} catch (e) {
  console.log(e.message)
} finally {
  로딩중 = false
}
```

## 클래스 (오호)
| 한남랭 | JS |
| --- | --- |
| `오호호호호~ 이름 {` | `class 이름` |
| `오호호호홋~ 이름 부모 {` | `class 이름 extends 부모` |

- 밈 원형: 한국 남자 웃음소리. 실제 발음은 "오콧콧콧"과 "오홋홋홋" 사이라 한글로 딱 떨어지지 않음. 표기는 `오호호호호~`, `오호호호홋~` 두 형태로 고정
- `오호호호호~`와 `오호호호홋~`는 둘 다 다섯 글자이고 마지막 글자(`호`/`홋`)만 달라서, 짝으로 기억하기 쉽고 눈으로도 구분됨
- `오호호호홋~` 헤더는 `요이~`처럼 첫 식별자 = 클래스 이름, 나머지 = 부모 클래스 식
- 형태 고정, 끝 `~` 필수: `오호~`, `오호호~`, `오호호호~`, `오호호호호호~`, `오호호호호`(물결 없음), `오콧콧콧~`, `오홋홋홋~` 등은 컴파일 에러
- `extends` 키워드를 JS 그대로 쓰는 `오호호호호~ 이름 extends 부모 {`는 에러 (상속은 `오호호호홋~`로만 씀)
- 클래스 본문(constructor, 메서드, 필드)은 JS 그대로. 메서드 안에서는 다른 밈 문법 사용 가능
- 클래스 표현식(`const A = class {}`)은 JS 그대로

## 출력 · 확인 (무슨 발언이세요?)
| 한남랭 | JS |
| --- | --- |
| `무슨 발언이세요? 값` | `console.log(값)` |
| `예? 무슨 발언이세요?(질문)` | `confirm(질문)` (예/아니오 확인) |

- 뉘앙스: 값이 이상할 때 찍어 보는 "지금 뭐라는 거야?"(console.log), 되물어 확인하는 "예? 무슨 발언이세요?"(confirm)
- `무슨 발언이세요?`는 문장 시작 위치에서만 인식. 쉼표로 여러 값 가능 (`무슨 발언이세요? a, b` → `console.log(a, b)`)
- 값은 여러 줄로 이어 쓸 수 있음. JS처럼 줄이 연산자·쉼표로 끝나거나 다음 줄이 `.`·`?.`·연산자로 시작하면 같은 값으로 읽음 (`아... 줴줴이야...`도 같음)
- **띄어 쓰는 형태만 허용.** `무슨 발언이세요?("a")`처럼 괄호를 붙이면 컴파일 에러 (띄어 쓰라고 안내)
- `무슨 발언이세요? (a, b)`처럼 쉼표 목록을 괄호로 감싸면 컴파일 에러 (JS 쉼표 연산자가 되어 `b`만 출력되기 때문). `무슨 발언이세요? (a + b) * 2`처럼 계산을 묶는 괄호는 허용
- `예? 무슨 발언이세요?(질문)`은 값 위치에서 인식하고 `true`/`false`를 돌려줌
- if 조건으로 쓸 때는 `예? 예? 무슨 발언이세요?(질문) {`. 문장 맨 앞의 `예? 무슨 발언이세요?(질문) {`는 컴파일 에러 (가장 긴 형태 우선 규칙상 confirm 뒤에 블록이 붙은 형태라, `예? 예? ...`로 쓰라는 안내를 띄움)
- 텍스트 입력(`prompt`) 설탕은 없음. 필요하면 `prompt()`를 JS 그대로 사용
- `무슨 발언이세요??`처럼 물음표 개수가 다르거나 띄어쓰기가 다른 형태는 컴파일 에러

```
무슨 발언이세요? "할 일 추가됨"
무슨 발언이세요? `할 일 ${할일들.length}개`
무슨 발언이세요? "현재 필터:", 필터

엄.. 지울까 = 예? 무슨 발언이세요?("완료한 할 일을 지울까요?")

예? 예? 무슨 발언이세요?("전부 지울까요?") {
  할일들.length = 0
}
```
```js
console.log("할 일 추가됨")
console.log(`할 일 ${할일들.length}개`)
console.log("현재 필터:", 필터)

const 지울까 = __hn.confirm("완료한 할 일을 지울까요?")

if (__hn.confirm("전부 지울까요?")) {
  할일들.length = 0
}
```

- `console.log`는 브라우저와 Node 양쪽에 있으므로 그대로 변환
- `confirm`은 Node에 없으므로 런타임 `__hn.confirm` 사용 (브라우저는 `window.confirm`, Node는 터미널에서 y/n 입력)

## 모듈
- `import`/`export`는 JS 그대로 (`export` 뒤는 문장 시작 위치라 `export 티-원 …`, `export 오호호호호~ …` 가능)
- `.hn` 파일끼리 import할 때는 경로에 `.hn` 확장자를 씀. 확장자 생략(`"./store"`)은 에러 (ESM 규칙과 동일)
- 실행 방식별 처리
  - `hannam`(Node 로더 훅), Vite 플러그인: `.hn` 경로를 그대로 처리
  - `hannamc`(컴파일): 상대 경로 import의 `.hn`을 `.js`로 바꿔 출력 (`"./store.hn"` → `"./store.js"`). 문자열 리터럴 경로의 동적 `import("./x.hn")`도 같음
  - 패키지 이름 import(`"node:http"`, `"vite"`)는 건드리지 않음

```
import { 할일추가 } from "./store.hn"
export 티-원 초기화() {
  할일추가("첫 할 일")
}
```
```js
// hannamc 출력
import { 할일추가 } from "./store.js"
export function 초기화() {
  할일추가("첫 할 일")
}
```

## 인식 규칙
- 문자열·템플릿 리터럴·주석·정규식 안은 변환 안 함
- 단, 템플릿 리터럴의 `${}` 안은 코드이므로 변환함. 값 위치 밈(`티~원!`, `예? 무슨 발언이세요?`)만 올 수 있고 문장 키워드는 올 수 없음 (`` `${티~원! 개수()}개` `` → `` `${await 개수()}개` ``)
- 가장 긴 형태 우선 (`예? 무슨 발언이세요?` > `예???` > `예??` > `예?`, `엄...` > `엄..` > `엄.` > `엄`, `아뇨아뇨아뇨아뇨` > `아뇨`)
- 둥근 따옴표 `“ ” ‘ ’`: 문자열·템플릿 리터럴·주석 안에서는 그대로 두고, 코드에 나오면 컴파일 에러 (JS와 동일). 모바일 키보드 자동 변환으로 들어간 경우가 많으므로 "일반 따옴표로 바꾸세요"라고 위치와 함께 안내
- `…`(말줄임표 한 글자)는 `...`(마침표 3개)와 다른 글자: 밈 키워드는 마침표만 인식 (`엄...`, `아... 줴줴이야...`). `엄…`, `아… 줴줴이야…`처럼 코드에 `…`가 나오면 컴파일 에러이고, 모바일 자동 변환일 가능성이 높으므로 "마침표 3개로 바꾸세요"라고 안내. 문자열·주석 안에서는 그대로 둠

### 문장 시작 위치
문법 키워드는 문장 시작 위치에서만 인식한다. 문장 시작 위치는 다음과 같다.
- 파일 맨 앞, 줄의 첫 토큰 (앞의 공백 무시)
- `{` 바로 뒤, `}` 바로 뒤 (`} 예??`, `} 아뇨아뇨아뇨아뇨`, `} 지~랄`)
- `;` 바로 뒤
- `export`, `export default` 바로 뒤 (`export 티-원 할일추가() {`, `export 오호호호호~ 할일 {`)

### 값 위치
값 위치에서도 인식: `티~원!`, `예? 무슨 발언이세요?` (JS에선 원래 문법 오류인 형태라 충돌 없음)

### 공백 경계
- `엄`, `엄.`, `엄..` 뒤에는 공백이 와야 함 (`엄.length`는 멤버 접근)
- `요이~`, `요히~`, `요이이이~`, `오호호호호~`, `오호호호홋~` 뒤에는 공백이 와야 키워드

### 헤더 자르기
`예?`, `예??`, `예???`, `요이~`, `요히~`, `요이이이~`의 헤더(조건·대상)는 **괄호 깊이 0에서 처음 나오는 `{` 직전까지**다.
- `()`, `[]` 안의 `{`는 무시하므로 `예? 목록.some(x => { ... }) {`처럼 조건 안의 화살표 함수 블록과 여러 줄 조건이 동작함
- 헤더 맨 앞의 객체 리터럴은 괄호로 감싸야 함 (`예? ({ a: 1 }).a {`)
