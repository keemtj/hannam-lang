# hannam-lang 프로젝트 맥락

> 문법 상세는 `hannam-lang-syntax.md` 참고. 이 문서는 그 외 논의 흐름, 결정 이유, 기각된 안, 로드맵을 정리한 것.

## 한 줄 요약
한남 말투 밈 11개로 쓰는 **JS 상위 호환 언어**. 엄랭(엄준식 랭)의 "시즌2" 콘셉트로, 장난 언어가 아니라 **웹 개발에 실제로 쓸 수 있는 수준**이 목표.

## 목표
- `.hn`으로 쓰고 JS로 변환해서 브라우저와 Node 양쪽에서 실행
- 최종 데모: **프론트와 서버 모두 `.hn`으로 짠 풀스택 투두** (CRUD, 완료 토글, 필터, 저장)
- 순수 esolang은 "만들 수 있냐"가 퍼즐이지만, 한남랭은 "실제로 쓸 수 있냐"가 목표

---

## 출발점: 엄랭 조사 요약
- 2020-06-26 공개, rycont/umjunsik-lang. 최초 구현은 Deno(TS), 이후 Node 포팅·Python·웹엄·C 컴파일러(엄씨)·C#·Go·Java·Kotlin·Rust·VBA 구현체. 원 레포 마지막 커밋 2024-05
- 문법: 정수·번호 변수(`어` 개수)·goto(`준`)·조건(`동탄`)·입출력(`식`)이 전부. 문자열 자료형 없음(유니코드로 한 글자씩 출력은 가능)
- **실용 한계**: 텍스트 입력 불가(정수만), 배열 없음(변수 번호가 코드에 고정), 화면 없음, 저장 없음 → 투두는 "숫자 콘솔 장난감" 수준이 최대
- **웹엄**: 언어 확장이 아니라 브라우저 실행기. HTML 52줄 + JS 136줄, `setInterval`로 한 줄씩 실행, 속도 슬라이더, 변수 디버그 창 → 플레이그라운드 아이디어로 참고
- npm에 엄랭 패키지 없음 (`umjunsik*` 비어 있음, `umlang`은 npm 보안 홀딩). Rust 컴파일러만 crates.io `umjunsik`(Lamina IR 타깃, 2025-10)
- 다른 한국 밈 언어로 `node-woojin`(npm) 존재

## 사용 밈 원본 정의 (사용자 설명)
- **엄.** — 엄준식 밈에서 유래. `엄.` `엄..` `엄…`까지. 할 말 없을 때, 생각할 때, 거의 모든 추임새 시작
- **예?** — `예??` `예???`처럼 물음표가 늘어남. 의문문에 씀
- **요이** — `요이~`, `요이이이`, `요이이이~`. 물결은 항상 맨 뒤. 기분 좋을 때
- **요히** — 요이에서 이를 히로 바꾼 형태
- **줴줴이야** — GG에서 변형. `아! 줴줴이야~`, `아… 줴줴이야…`. 앞에는 `아`만 옴. 이겼을 때/졌을 때 둘 다, 말줄임표는 주로 졌을 때
- **오호호호호** — 한국 남자 웃음소리. 호를 더 붙일 수 있음, 끝에 `~` 가능. 기분 좋을 때. 실제 발음은 "오콧콧콧"과 "오홋홋홋" 사이라 한글 표기로 특정하기 어려움 (표기는 `오호호호호~`/`오호호호홋~`로 고정)
- **무슨 발언이세요?** — `예? 무슨 발언이세요?`처럼도 사용. 상대 말이 황당하거나 어이없을 때 쓰는 반응
- **아뇨아뇨아뇨아뇨** — 부정. 4번이 기본, 끝에 `!`로 강조
- **티-원 / 티~원** — LoL T1에서 유래. `-`, `~`가 티와 원 사이. `티~원!`도 사용
- **진~지?** — 상대를 놀리거나 장난쳤는데 진지하게 반응하면 그에 대한 리액션. "너 왜 이렇게 진지해?" 느낌
- **지~랄** — 누군가 말을 하면 "지~랄" 하면서 받아 줌. "아 진짜?", "really?" 같은 리액션

## 주요 결정과 이유

| 결정 | 이유 |
| --- | --- |
| **JS 상위 호환** (밈만 JS로 변환, 나머지 통과) | ES6+ 전체와 DOM·fetch·Node 생태계를 공짜로 얻음. 전부 밈으로 표현하는 안은 키워드가 모자라고 JS 명세 전체를 직접 파싱해야 해서 비현실적 |
| **플랫폼 API는 JS 그대로** | TypeScript가 DOM 이름을 안 바꾸는 것과 같은 논리. 대신 자주 쓰는데 보기 싫은 패턴만 **문법 설탕**으로 감쌈 (예: `throw new Error` → `아... 줴줴이야... "문자열"`) |
| **설탕 우선** | 설탕이 있는 곳에선 JS 문법 대신 설탕을 씀 |
| **중괄호 블록** | 들여쓰기·콜론 방식까지 검토했으나 리액트·넥스트를 매일 쓰는 감각과 섞여 더 헷갈려서 JS 스타일로 복귀. 조건 괄호는 선택, 세미콜론 생략 |
| **한 형태 = 한 문법** | 같은 뜻의 별칭은 var/let/const처럼 헷갈림. 밈 변형은 각각 다른 문법이어야 함 |
| **ESM 출력 기본** | 함수 밖 `티~원!`(top-level await)이 ES 모듈에서만 됨. CJS 출력을 지원하게 되면 컴파일러가 async 함수로 자동 래핑 |
| **둥근 따옴표는 JS처럼 컴파일 에러** | 처음엔 일반 따옴표로 바꿔 주는 정규화를 검토했으나, 문자열 안의 UI 문구(`"“완료” 항목"`)까지 바뀌어 깨지는 문제가 있음. JS와 같은 기준(문자열 안은 글자, 코드에 나오면 에러)이 예측하기 쉬움. 모바일 자동 변환은 친절한 에러 메시지로 대응. `…`도 `...`와 다른 글자로 엄밀히 구분: 밈 키워드는 마침표 3개(`엄...`, `아... 줴줴이야...`)만 인식하고 `…`는 코드에 나오면 에러. 마침표를 택한 이유는 `엄`→`엄.`→`엄..`→`엄...` 점 개수 규칙과 이어지고 키보드로 바로 칠 수 있어서 |
| **이번 버전은 한남 말투 11개만** | 일반 인터넷 밈은 다음 버전에서 검토. 채택 기준: 뉘앙스가 역할과 맞을 것, JS 기호와 충돌 없을 것, 오래 갈 밈일 것 |
| **엄랭 크레딧 명시** | 다른 파생 언어들처럼 "rycont/umjunsik-lang에 영감을 받아 제작" |

### 이름 · 배포
- 정식 명칭 **hannam-lang**, 확장자 **`.hn`**
- 명령어: **`hannam app.hn`**(실행, node·tsx 역할) / **`hannamc app.hn`**(컴파일 → `app.js`, tsc 역할)
- npm 확인(2026-10-22): `hannam-lang`, `hannam`, `hannamc` 비어 있음
- 회피: `hnc`(해커뉴스 CLI 패키지, 등록 명령어가 `hn`), `hn`(Drupal 관련 패키지)
- 배포 전 재확인 필요. 선점돼 있으면 스코프 패키지로

## 검토 후 기각 · 보류한 안
- **다른 esolang 결합** (LOLCODE 구조, ArnoldC 연산자 대사, Rockstar 별칭) → 취소. 참고 자료로만
- **파이썬식 들여쓰기 블록**, **콜론 블록 헤더** → 헷갈려서 중괄호로 복귀
- **`요이~`·`요히~` 둘 다 true** → 중복이라 기각. 반복문 짝(for...of / for...in)으로 변경
- **`요히~` = 불리언 토글**, **`continue`** → 제안했으나 반복문 짝 채택
- **`||` / `??`를 요이·요히로** → JS에서도 헷갈리는 짝이라 보류
- **`엄...` = debugger 또는 구현 예정 자리표시** → 주석 유지
- **출력 후위(`값 오호호호호~`)** → 전위(`오호호호호~ 값`) 채택. 이후 `오호호호호~`는 class로 옮기고 출력은 `무슨 발언이세요? 값`으로 바뀜
- **숫자 리터럴을 이 개수로(`요이이이` = 3)** → 실용성 없어 제외
- **`아뇨아뇨아뇨아뇨!` = `!` 별칭** → 기각. 한 글자 연산자를 긴 밈으로 바꾸는 별칭이라 가독성만 떨어지고, `else`(`아뇨아뇨아뇨아뇨`)와 `!` 하나 차이라 오타 시 의미가 조용히 바뀜
- **`무슨 발언이세요?(질문)` = 텍스트 입력(`prompt`)** → 기각. 실제 웹은 `<input>`·폼, 서버는 HTTP 요청으로 입력을 받아 쓸 일이 거의 없고, Web Worker 플레이그라운드에서는 `prompt`를 쓸 수 없음
- **`예? 무슨 발언이세요?` = switch case** → 기각. case는 정상 경우라 "황당함" 뉘앙스와 반대이고, 갈래마다 반복돼 길어지기만 함
- **일반 밈 후보** (`ㅇㅇ`/`ㄴㄴ` true/false, (try/catch는 한남 말투 `진~지?`/`지~랄`로 채움), `펌` import), **`"문자열" 까지가 템플릿`** → 다음 버전 후보

## 아키텍처 계획

### 레포 구조 (pnpm 모노레포)
```
packages/
  core/          # 변환기 (렉서 → JS 출력, 소스맵)
  cli/           # hannam, hannamc
  vite-plugin/   # .hn import → JS (HMR)
  vscode/        # 문법 하이라이팅
apps/
  playground/    # 웹 플레이그라운드
examples/
  todo/          # 프론트 + 서버
```

### 변환기 핵심 설계
- 밈 토큰을 **가장 먼저, 가장 긴 형태로** 매칭
- 문자열·템플릿 리터럴·주석·정규식 안은 변환 제외
- 문법 키워드는 **문장 시작 위치에서만** 인식 (`a ? b : c`, `티 - 원` 같은 일반 JS와 충돌 방지)
- 값 위치 인식은 JS에서 원래 문법 오류인 형태만 (`티~원!`, `예? 무슨 발언이세요?`)
- 기호 충돌 주의 목록: `티-원`(뺄셈), `예?`(삼항·옵셔널 체이닝), `~`(비트 NOT), `엄.`(멤버 접근), `!`(논리 NOT), `...`(스프레드)
- 런타임 헬퍼 `__hn`: `toError`(문자열이면 Error로 감싸고 Error면 그대로), `confirm`(브라우저는 window.confirm, Node는 y/n 입력 헬퍼). 텍스트 입력 `ask`는 삭제
- 에러 위치가 `.hn` 원본에 맞게 나오도록 **소스맵** 필수
- 변환 이후 검증은 필요하면 Babel/esbuild에 넘김

### 명세 = 테스트
- 명세를 `.hn` ↔ `.js` 예제 짝으로 작성 → 그대로 vitest 스냅샷 테스트 케이스로 사용

### CLI
- `package.json`의 `bin`에 `hannam`, `hannamc` 등록 + 실행 파일 맨 위 `#!/usr/bin/env node`
- `hannam`은 메모리에서 변환 후 실행, Node 로더 훅 등록으로 `.hn`끼리 import 지원
- 로컬 테스트는 `npm link`

### 플레이그라운드
- Monaco 또는 CodeMirror, 키워드 하이라이팅
- Web Worker에서 실행 + 실행 스텝 제한(무한루프 방지)
- URL 해시에 코드 압축 저장해 링크 공유
- `.hn`과 변환된 JS 나란히 보기, 웹엄처럼 한 줄씩 실행 + 변수 상태 보기 (토큰·AST 시각화로 확장 가능)
