# JS → hannam-lang 역변환 명세

> 상태: 0.1.1에서 구현 (`@hannam-lang/core/migrate`, `hnc --from-js`, Playground의 JS 가져오기). 문법 자체는 `hannam-lang-syntax.md`가 기준이고, 이 문서는 기존 JS를 `.hn`으로 옮기는 도구의 규칙만 다룬다.

## 목적
이미 있는 JS 코드베이스를 한남랭 키워드로 옮긴다. "내 코드를 한남랭으로 바꿔 보세요"를 한 번의 명령으로 할 수 있게 하는 것이 목표.

## 원칙
1. **의미 보존이 최우선.** 바꾼 `.hn`을 다시 컴파일한 결과는 원래 JS와 같은 동작이어야 한다. 확신할 수 없으면 바꾸지 않는다.
2. **바꾸지 못하면 JS 그대로 둔다.** 한남랭은 JS의 상위 집합이라 JS 그대로인 부분도 유효한 `.hn`이다. 그래서 변환은 실패하지 않고 "바꿀 수 있는 만큼만" 한다.
3. **서식은 보존한다.** 들여쓰기, 따옴표, 세미콜론, 줄바꿈(CRLF 포함), 주석 위치를 바꾸지 않는다. 키워드 부분만 원래 자리에서 고친다.
4. **바꾸지 못한 곳은 이유와 함께 보고한다.**

## 동작 방식
- **파싱**: acorn으로 JS를 ES 모듈(`sourceType: "module"`, `ecmaVersion: "latest"`)로 파싱해 AST와 노드 위치를 얻는다. 파싱에 실패한 파일(JSX, TypeScript, 문법 오류)은 파일째 건너뛴다.
- **수정**: 정방향 컴파일러처럼 magic-string으로 노드 위치의 글자만 고친다. AST에서 코드를 다시 생성하지 않는다.
- **검증**: 바꾼 결과를 `compile()`로 다시 JS로 만들고, 원래 JS와 AST를 비교한다(위치·주석 정보 제외). 다르면 문장 단위로 되돌려 가며 원인 문장을 찾고, 그 문장만 JS로 남긴다.
  - `switch`, `confirm`, `throw new …`처럼 컴파일 결과가 원래 JS와 다른 모양이 되는 변환은, 원래 JS에 같은 변환을 적용한 "기대 AST"와 비교한다.

## 변환 규칙

### 항상 바꾸는 것
| JS | hannam-lang | 조건 |
| --- | --- | --- |
| `var` / `let` / `const` 선언문 | `엄` / `엄.` / `엄..` | 문장으로 쓰인 선언. `for` 헤더 안의 선언은 반복문 규칙을 따름 |
| `if (조건) {` | `예? 조건 {` | 본문이 블록일 때. 조건이 `{`로 시작하면(객체 리터럴) 괄호를 남김 |
| `} else if (조건) {` | `} 예?? 조건 {` | 위와 같음 |
| `} else {` | `} 아뇨아뇨아뇨아뇨 {` | |
| `while (조건) {` | `요이이이~ 조건 {` | 본문이 블록일 때 |
| `break` / `continue` | `줴줴이야` / `아뇨` | 레이블 없는 경우만 |
| `return 값` | `아! 줴줴이야~ 값` | |
| `function 이름(` | `티-원 이름(` | 함수 선언문만 (`export`, `export default` 뒤 포함) |
| `async function 이름(` | `티~원 이름(` | 위와 같음 |
| `await 식` | `티~원! 식` | 값 위치 포함. `for await`는 제외 |
| `class 이름 {` | `오호호호호~ 이름 {` | 클래스 선언문만 |
| `class 이름 extends 부모 {` | `오호호호홋~ 이름 부모 {` | 위와 같음 |
| `try {` / `catch (e) {` | `진~지? {` / `지~랄 e {` | `finally`는 JS 그대로 |
| 문장으로 쓰인 `console.log(인자)` | `무슨 발언이세요? 인자` | `console`이 지역 변수로 가려지지 않았을 때 |

### 조건이 맞을 때만 바꾸는 것
| JS | hannam-lang | 조건 (안 맞으면 JS 그대로) |
| --- | --- | --- |
| `for (const x of 목록) {` | `요이~ x 목록 {` | 선언이 `const`일 때만 (`요이~`는 `const`로 컴파일됨). `let`이나 선언 없는 형태는 제외 |
| `for (const k in 객체) {` | `요히~ k 객체 {` | 위와 같음 |
| `for (let i = a; i < b; i++) {` | `요이~ i a..b {` | 선언자 하나, 비교가 같은 변수의 `<`, 증가가 `i++`일 때만 |
| `switch (값) { … }` | `예??? 값 { … }` | 모든 `case`가 `break`·`return`·`throw`·`continue`·레이블 `break`로 끝나고(마지막 case는 예외), 그 밖에 switch를 빠져나가는 `break`가 없고, `default`가 마지막일 때. 끝의 `break`는 `}`로 바꾸고, 빈 `case`가 이어지면 `"a",` / `"b" {`로 묶음. 블록으로 감싼 case, 한 case에서 선언한 이름을 다른 case나 case 조건에서 쓰는 경우는 제외 (JS의 case 조건은 switch 블록 안에서 평가되어 그 이름을 보지만, `.hn`에서는 블록 밖 if 조건이 됨) |
| `throw new X(…)` | `아... 줴줴이야... new X(…)` | `new`로 만든 값을 던질 때만. 문자열·식별자를 던지면 컴파일 결과가 `new Error(…)`·`__hn.toError(…)`로 바뀌어 동작이 달라지므로 제외 |
| `confirm(질문)`, `window.confirm(질문)` | `예? 무슨 발언이세요?(질문)` | 전역 `confirm`이고 인자가 있을 때만 (지역 변수로 가려진 경우, 인자 없는 `confirm()`은 제외. 헬퍼가 `String(undefined)`를 띄움) |

### 바꾸지 않는 것
- 대응하는 키워드가 없는 문법: `do...while`, 레이블 문, `for await`, 제너레이터, `finally`, 화살표 함수, 메서드, 함수·클래스 표현식, 일반 `for` 문
- 본문이 블록이 아닌 `if`/`while`/`for` (`if (a) b()`)
- 여러 줄에 걸친 `console.log(…)`, 인자 끝에 쉼표가 있는 `console.log(…)` (다음 버전 후보)
- 주석: `//`, `/* */` 모두 그대로. `//` → `엄...` 변환은 옵션으로만 제공하고 기본값은 끔. 블록 주석을 `엄...` 여러 줄로 바꾸는 것은 범위 밖

## 이름 충돌
파일에 `__hn`으로 시작하는 이름이 있으면 `switch`와 `confirm`은 바꾸지 않는다. 컴파일러가 만드는 런타임 헬퍼(`__hn`)와 switch 임시 변수(`__hn_s0` …)를 사용자 이름과 구분할 수 없기 때문이다.

문장 맨 앞에 키워드와 같은 이름이 오는 JS는 `.hn`에서 키워드로 읽혀 그대로 둘 수 없다 (예: 변수 `아뇨`, `줴줴이야`에 값을 대입하는 문장). 변환으로 해결할 수 없으므로 파일 단위 오류로 보고하고, 이름을 바꾸라고 안내한다.

## 파일 단위 규칙
- 대상: `.js`, `.mjs`. `.cjs`, `*.min.js`, 한 줄이 1000자를 넘는 파일, `node_modules`, 점으로 시작하는 폴더, `.gitignore`에 든 파일(git 저장소 안일 때)은 제외
- CommonJS(`require`, `module.exports`, `exports.x`, `__dirname`)를 쓰는 파일은 `.hn`에서 실행되지 않으므로 건너뛰고 이유를 보고
- import 경로: 실제로 `.hn`을 만드는 파일을 가리키는 상대 경로의 `.js`만 `.hn`으로 바꾼다. 옮기지 못한 파일(CommonJS, 압축, 이미 `.hn`이 있음)을 가리키는 경로, 확장자 없는 경로, 패키지 이름은 그대로
- 같은 `.hn`으로 바뀌는 파일(`a.js`, `a.mjs`)이 함께 있으면 둘 다 옮기지 않는다
- `.gitignore`는 폴더를 훑어 찾은 파일에만, 그 폴더가 속한 저장소 기준으로 적용한다. 직접 지정한 파일은 거르지 않는다
- `--comments`도 파일 맨 앞의 `#!`는 건드리지 않는다

## 보고 형식
```ts
interface MigrateResult {
  code: string
  /** 실제로 적용한 변환 수 */
  changes: number
  /** 바꾸지 않고 JS로 남긴 곳 */
  skipped: { line: number; column: number; kind: string; reason: string }[]
}
```

## 서식과 도구
- 원본 서식은 그대로 남는다. 서식을 정리하고 싶으면 **변환 전에** 원래 formatter를 돌리도록 안내한다.
- Prettier, ESLint, Biome은 `.hn`을 읽지 못한다. 옮긴 파일에서는 기존 formatter와 linter를 쓸 수 없다는 점을 문서와 CLI 출력에 분명히 알린다.
- `eslint-disable` 같은 지시 주석은 의미가 없어지지만 그대로 둔다.

## 검증 계획
- 단위 테스트: 위 규칙마다 "바꾸는 경우 / 조건이 안 맞아 남기는 경우" fixture 쌍
- 왕복 테스트: 상위 호환 테스트와 같은 corpus(acorn, magic-string, lodash-es의 JS 648개)를 변환 → 다시 컴파일 → AST 비교. 의미가 달라진 파일 0개가 통과 기준
- 0.1.1 기준 결과: 648개 모두 변환, 7,117곳을 바꿨고, 검증에서 걸러진 곳 0곳

## 제공 형태
1. **API**: `migrate(js, options) → MigrateResult`
2. **CLI**: `hnc --from-js <파일|디렉터리>`. 기본은 바뀔 내용만 보여 주고(diff), `--write`를 줘야 `.hn` 파일을 만든다
3. **Playground**: 툴바의 "JS 가져오기"에 붙여 넣으면 `.hn`으로 바꿔 편집기에 넣는다 (주석도 `엄...`으로 바꿈)

## 패키지 배치
새 패키지를 만들지 않고 기존 패키지에 넣는다.
- API는 `@hannam-lang/core`의 별도 진입점 `@hannam-lang/core/migrate`로 둔다. `compile`만 쓰는 쪽(Vite 플러그인, 로더 훅)은 파서를 불러오지 않는다.
- acorn이 `@hannam-lang/core`의 의존성으로 추가된다 (지금은 테스트용 devDependency).
- CLI는 `hannam-lang` 패키지의 `hnc`에 옵션으로 추가한다. 파서는 `--from-js`를 줄 때만 불러온다.
- `hannam-lang/migrate`로도 같은 API를 내보낸다. pnpm처럼 직접 설치하지 않은 패키지를 막는 환경에서도 쓸 수 있게 하려는 것이다.

## 결정한 것
- `--write` 뒤 원래 `.js`는 지우지 않고 남긴다. 이미 있는 `.hn`은 덮어쓰지 않는다
- `//` → `엄...`은 `--comments`(API는 `comments: true`)로만 켠다. 기본값은 끔
- 여러 줄 `console.log` 변환은 첫 버전에서 뺀다
